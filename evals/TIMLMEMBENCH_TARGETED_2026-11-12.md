# TimlMemBench 中文 dev：写入与来源题配对复测

日期：2026-11-12。目标是诊断记忆链路，不把本子集成绩称为完整 benchmark 分数。

## 协议与核验

- 从官方 `raw_native_cases` 中文 dev 中，仅按公开 `case_type` 选 `write_op_accuracy` 10 题和 `provenance_recoverability` 8 题，共 9 个样本。适配器提取、回答均不读取金标准；官方裁判单独读取金标准评分。
- 首组对 61 段原始会话提取一次，生成 281 条候选事实；后两组从同一候选文件重放 61 段，提取模型调用均为 0。候选文件只存提取事实，不存原始会话或金标准。三组问题 ID、顺序完全对齐；54 条评分均成功解析。
- 三组使用同一 AgentScope `deepseek-v4.1-flash-1017` 回答模型和 DeepSeek 裁判。基础组关闭治理及来源提示；来源组只加当前召回记忆的来源锚点；治理组再做撤销、更正、保留识别并提供最小操作轨迹。独立生成和同模型裁判仍可能波动，故逐题变化仅作诊断。
- 冻结候选的 SHA-256、逐题对照和 token 记录在 `results/tables/timlmembench_targeted_full_summary.{json,md}`。原始预测、评分及候选含 benchmark 内容，发布前需核对数据许可；密钥未写入文件。

## 失败分析

1. **同一旧许可残留多个副本。** `T0086Z__gb001` 中治理组已做一次更正，回答却仍把旧门码 2705 当成有效进入规则。现有操作只变更一条目标记录，提取产生的其他同义记录仍参与召回。这是适配器提取与逐记录治理的交互缺陷；真实产品是否同样发生，要在产品写入链路复现后判断。
2. **来源在存储和召回中，但回答没有稳定使用。** 8 道来源题的召回 ID 都带源轮次；显式写出 `Session N` 或 `sNNN_tNNN` 的回答数分别仅 0/8、1/8、3/8。`T0095Z__gb006` 的召回含 Session 5 的 `t004/t006`，回答仍声称无法指出原始轮次。当前来源提示只给简短 ID、没有授权原话，且与普通人格提示混在一起；需要独立的证据呈现格式和回答约束。
3. **操作轨迹可能干扰来源排序。** `T0097Z__gb005` 在基础和来源组均判对，治理组加入一个 revoke 轨迹后判错，遗漏了同一 Session 4 的蓝色保温袋与拍照通知。`T0092Z__gb005` 的来源组已召回 Session 2 的一条证据，治理组却偏重 Session 5 的更正轨迹与 Session 7 的确认，漏掉核心撤销链。不能把所有允许空间的操作事件无差别注入解释题。
4. **写入分类题与普通 Top-5 召回不等价。** 多道题要求审视一个样本中的 `add/revoke/preserve/skip/update` 全序列，而当前回答只见相关度最高的 5 条当前记忆。历史写入、跳过候选和已撤销条目不在此视图中；模型容易回答一般规则或“证据不足”。这首先是评测适配视图缺口，不代表产品的普通聊天应默认展示全部历史或已删除原文。
5. **操作目标识别仍不稳。** 治理组 24 个候选未通过目标校验；本次日志只有汇总类别，不能再判定缺少提取目标、目标已失效、主体不符或跨空间。细分拒绝码已加入，下一次短测应核对分布。不能为追分放松本人、空间和原文证据门禁。

## 下一步

- 用产品写入路径建立“同一事实多条摘要，明确更正后全部旧副本不得召回”的离线复现；若复现，再设计事实实体/版本或关联失效机制。
- 来源查询独立取当前有效事实的授权源发言、时间和更正链；已删除原文不可通过追溯复活。只给与问题相关的来源，避免操作轨迹噪声。
- 为写入分类题提供受控的候选操作审计视图，记录 `add/revoke/preserve/skip/update` 的决策与拒绝原因；它应与普通聊天召回视图区分。
- 完成上述改动后，先以冻结候选复测这 18 题，再运行完整 dev；holdout 不用于调参。

本轮适配器与模型离线测试：11 项通过。实际 API 已运行三组各 18 题；**没有重跑完整 dev、train 或 holdout**。

最初 18 题中有 6 题通过，递进复测又使 9 道原失败题通过；按各题**最后一次作答**统计为 15/18。这个混合数字只用于缺陷跟踪，**不是同一适配器版本的一次完整 benchmark 成绩**；之前通过的 15 题并未全部在 v5 重测，也不能排除回归。

当前仍失败：

- `T0091Z__gb001`：漏掉初始 add 和旧书签 skip，把当天临时边界当作长期 preserve。
- `T0092Z__gb005`：只回溯 Session 7 的确认，漏掉 Session 2 的核心撤销证据链。
- `T0093Z__gb001`：给出一般写入分类规则，却没有逐项分类该样本的 add/revoke/preserve/skip/update。

这三题暴露的主要缺口是：当前只记录“提取成功的事实”和“成功执行的更正”，没有每个候选的写入、跳过、临时化以及拒绝原因的完整决策日志；来源解释也未把旧许可到撤销的证据链建立为可检索关系。不能靠进一步堆叠提示词宣称产品 memory 已具备这些能力。已执行的离线测试为 14 项通过；本轮新增 API 预测与裁判合计约 307,313 tokens（v3 121,895；v4 117,109；v5 68,309），不等于账单金额。

结果文件分别为 `results/tables/timlmembench_targeted_failed_governed_{predictions,scores}.jsonl`、`timlmembench_targeted_failed_v4_{predictions,scores}.jsonl` 和 `timlmembench_targeted_failed_v5_{predictions,scores}.jsonl`。尚未运行同一最终版本的完整 18 题或完整 dev；**适配器仍不能认定无问题**。操作审计视图是 benchmark 诊断用，不代表普通聊天应展示这些历史信息；官方查询也没有真实受众 ACL。
