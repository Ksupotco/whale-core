## 已落实的代码

- 评测中的事实写入、更正、撤销改用产品 `FactService`；相同事实合并证据 ID，后续发言也可定位旧事实。
- `FactService.evidence_chain` 返回同一事实版本的来源锚点和生效状态，不返回旧正文。适配器能提供更正链与已撤销操作的来源 ID。
- 写入题试验了结构化 `skip`、`ephemeral`、`add_candidate`、`preserve_candidate` 判定，并保留逐题 trace 供分析。
- 提取上限可配置为 6–12。扩大到 12 后，61 段会话候选从 284 条增至 344 条，没有提分；新候选文件保存在 `E:\2026-1\tmp\timlmembench_factservice_v5_facts.json`。

## 失败指向

来源锚点可改善部分来源题，但不同完整运行仍有波动。写入题的主要失败是：历史 add 被当成当前有效；旧许可虽撤销，其别名仍可被引用；临时事项被当作长期事实；应保留的互动或分享边界未进入当前状态。单纯扩大候选数使噪声增加。下一轮应把写入决策和事实版本状态做成明确的产品数据，再让评测适配器读取同一状态，而不是继续靠回答提示重建整段历史。

原始结果见 `results/tables/timlmembench_factservice_v{1,3}_full_{predictions,scores}.jsonl`、`timlmembench_factservice_v3_write_{predictions,scores}.jsonl`、`timlmembench_factservice_v5_write_{predictions,scores}.jsonl`。复测脚本为 `evals/run_timlmembench_fact_regression.ps1`，同题比较脚本为 `evals/compare_timlmembench_runs.py`。

## v4 完整重跑（2026-11-13）

使用相同 18 题、冻结的事实候选、DeepSeek `deepseek-v4.1-flash-1017` 治理/回答/裁判；18 题全部生成并评分，裁判解析失败 0。与 v3 配对比较：来源题两道改善（0096、0098）、一道退步（0091）；写入题一道退步（0097）；分类总数均不变。与旧版 v5 比较则是三道改善、三道退步。

本次适配器通过产品 `FactService.apply_candidate` 提交新增、更正、撤销，撤销现在保留失效版本而不是物理删除。**但冻结的候选没有 `slot_key`，适配器也没有从模型产出槽位；新增的同槽冲突待定逻辑没有被这次评测触发。** `decision_trace` 中的 `skip` / `ephemeral` 仍是适配器诊断信息，尚未回写候选事实的产品决策状态，因此不能把 10/18 解读为该逻辑无效或有效。

8 道未过题中，5 道写入题主要涉及历史 `add` 当现行、短期信息过写、撤销/保留不完整、无关记忆过度激活；3 道来源题缺直接证据或归错说话人。比如 0091 有 38 条写入轨迹，虽另有 3 条 `ephemeral` 判定，临时事项仍进入了回答的写入清单。下一步需要让候选的操作与槽位在入库前生效，并让写入题从事实状态而不是冗长提示重建操作。

文件：`results/tables/timlmembench_factservice_v4_full_{predictions,scores}.jsonl`。该进程最终累计预测侧 79 次模型调用，144,892 输入 / 24,719 输出 tokens；另有裁判 18 次，16,592 输入 / 2,192 输出 tokens。合计 161,484 输入 / 26,911 输出 tokens。文件只记录用量，不包含服务商实际扣费金额。

## v5 候选入库决策修订与小试跑

适配器现先暂存冻结的提取候选，复用每段已有的治理模型调用，取得逐候选 `add/skip/ephemeral` 和可选 `slot_key`，再调用产品 `FactService` 入库。无期限的 `ephemeral` 不进入长期事实；同槽矛盾进入 `pending`；写入轨迹同时保留未入库决策。模型未给候选决策时保留原有 `add` 行为。旧的未写入发言诊断仍单列。

用 v4 未过题中的前两题做了三次付费小试跑，均为 1 道写入 + 1 道来源题，**不能当作完整 18 题分数**。第一次来源题通过、写入题未过，且有 1 次治理 JSON 解析失败；把治理输出上限从 768 提高到 1280 后，第二、三次解析失败均为 0，但两题仍未过。第三次已正确执行 2 次撤销、减少答案长度，仍将历史首次 `add` 与当前失效状态混淆，漏掉旧书签的 `skip`。来源题仍有说话人归属错误。

随后收紧了写入题的历史操作说明，并在授权来源上下文标注发言者及可用原话；该修订已纳入下方 v5 完整重跑。小试跑结果保存在 `results/tables/timlmembench_factservice_v5pilot{,2,3}_failed_{predictions,scores}.jsonl`，不能将小试跑与 v4 其它题拼成新总分。

## v5 同批 18 题完整重跑

沿用官方中文 dev 的同一批 18 题与冻结事实候选，以 DeepSeek `deepseek-v4.1-flash-1017` 做治理、回答及裁判。18 道预测和评分全部完成；治理 JSON 与裁判 JSON 均无解析失败。v4→v5：写入题 5/10→6/10，来源题 5/8→3/8，合计 10/18→9/18。三题改善（0093 来源、0094 写入、0097 写入），四题退步（0086 来源、0096 写入/来源混合、0097 来源、0098 来源）。

失败模式仍明确：写入题有临时内容过写、历史 `add` 与当前失效混淆、`preserve` 边界遗漏；来源题有核心发言锚点缺失、A/B 归属错误或把较晚的相邻发言当成原始证据。新候选闸门确实执行了 `skip/ephemeral/pending`，但回答没有稳定利用这些状态；来源题下降说明候选筛除和答案来源组织还需一起校准。现阶段不应把这一版称为提分。

## v6 本地修订（尚未付费评分）

治理模型漏给某条候选写入决策时，该候选现在进入产品 `pending` 状态并记下来源，而不是默认 `add`；普通召回、混合检索、会话摘要和当前事实计数会排除它。来源题从相关事实的当前及已失效版本组成事实族，再关联撤销和更正操作；已失效版本只提供状态与来源锚点，不恢复旧正文。普通问答仍只召回当前有效事实。写入题的候选操作现从 `FactService.decisions_for_evidence` 读取产品决策记录，清空适配器临时 `write_trace` 后仍能构建写入视图；未提取发言的诊断和操作目标锚点暂仍由适配器提供。相关本地回归 76 项通过，包括撤销后仍可追溯来源、旧正文不进入提示、漏判候选不可召回和历史写入决策可查询。另有 2 项混合检索测试因本机 pytest 临时目录权限错误无法创建测试目录，未计入通过数。

## v9 结构化支持来源与 v10 术语试验

v9 让治理模型为一次撤销/更正提出最多 3 条同会话、同说话人的支持发言 ID；适配器校验后将 ID 保存到产品 `FactService` 的决策记录，并在来源解释中按操作展示。相同冻结候选的完整 18 题为 **13/18**：写入 6/10，来源 7/8。相对 v7，旧钥匙来源题转对，猫粮规则写入题转错，总分不变；18 条裁判均可解析，治理 JSON 解析失败 0。17/29 个已执行操作带有支持发言。原始结果在 `results/tables/timlmembench_factservice_v9_full_{predictions,scores}.jsonl`。

v10 针对猫粮题把产品 `update` 明确表述为 benchmark 的 `supersede`。单题付费复测由 0/1→1/1，但完整 18 题只有 **12/18**（写入 6/10、来源 6/8）：该题转对，另有两题转错。18 条裁判及治理 JSON 均无解析失败。原始文件在 `results/tables/timlmembench_factservice_v10_full_{predictions,scores}.jsonl`，单题在 `timlmembench_factservice_v10pilot_failed_{predictions,scores}.jsonl`。v10 的术语提示与显示改动已撤回；当前代码保留 v9 的结构化支持来源。单题成功不能代替完整重跑。

从 v7/v9/v10 的翻转看，只冻结事实候选还不够：治理模型每轮仍重新生成操作和候选决策，回答与裁判也有波动。下一轮先把完整治理输出及其证据映射冻结为可回放输入，再分别比较存储/检索与回答层；不要继续通过叠加提示词和反复付费重跑来猜测因果。
