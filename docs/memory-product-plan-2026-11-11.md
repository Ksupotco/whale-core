# Whale memory：产品需求与 TimlMemBench 驱动的开发方案

状态：2026-11-12 需求访谈持续中；尚未实施产品改动。自动记忆的架构与代码分层草案见 [memory-architecture-v1-2026-11-12.md](memory-architecture-v1-2026-11-12.md)。产品体验优先，benchmark 用于诊断与回归，不能以单一裁判分数代替产品验收。已重新确认：亲密关系或心理健康倾诉继续使用现有云端 API 回复，默认不自动提取长期事实，但仍生成约 90 天的情绪事件；此前“敏感回复与提取都本地”的选择已被这一决定取代。

## 已确认的产品取舍

| 议题 | 决定 | 设计含义 |
| --- | --- | --- |
| 目标 | 真实陪伴产品优先 | 先解决错记、失效事实、权限错误，再优化 benchmark 分数 |
| 首个可体验版本 | 日常聊天更懂当下需求；实际重点是兴趣分享与讨论 | 先验收具体内容的接续、自然观点与相关追问；情绪倾诉保留基础场景，跨周画像与模仿草稿后续完善 |
| 自动写入 | 普通聊天中低风险、明确自述可自动记；可纠错 | 后台提取候选，写前校验说话人、证据、敏感性和空间 |
| 自动写入可见性 | 聊天中不逐条报备，记忆页展示新记录、来源及一键纠错/删除 | 降低打断；事实写入仍可被本人发现和撤销 |
| 时效 | 回复先发出，数秒内后台写入；本会话可用原话 | 不把云端提取放在回复必经路径；异步任务须幂等、可重试 |
| 身份与空间 | owner 私有记忆跨自己的设备共用；对其他人默认不分享 | 服务端身份解析决定读写空间，不能让回答模型自行保密 |
| 分享 | 只对指定事实、对象开放，可撤回；未给期限默认 24 小时 | 授权是有范围、有效期、版本的记录；撤回立即使读取失效 |
| 分享后更正 | 旧版本立即失效；新版本须本人重新授权 | 分享授权绑定事实版本，更正不能悄悄扩大已授权内容 |
| 更正 | 本人明确更正则自动替换；含糊冲突先询问 | 旧事实立即退出召回，保留可授权查看的更正来源链 |
| 含糊冲突的询问时机 | 先暂停受影响的主动提醒；仅在本人要安排提醒或冲突影响当前回答时自然询问 | 不因一条模糊近况立刻打断聊天，也不继续执行可能过时的提醒 |
| 删除 | 区分“忘掉长期记忆”和“彻底删除记录” | 前者删除精选记忆及索引；后者还处理关联历史、派生物与备份恢复策略 |
| 删除与备份 | 彻底删除后在线立即失效；旧离线备份最多保留 30 天 | 每次恢复必须先重放删除记录，防止旧内容复活；备份到期物理清除 |
| 来源解释 | 日常自然回答；追问时给原话、时间、更正链 | 来源解释走单独的授权查询，不在每次回复里铺满证据 |
| 来源片段保留 | 有效记忆的证据原话片段随记忆保留；更正旧片段最多再留 30 天 | 之后只留不含原话的更正链；忘掉该记忆时清理其专属证据片段，彻底删除立即优先 |
| 主动行为 | 仅明确授权的事项可触发提醒、发消息或行动 | 事实记忆本身不是行动授权；执行时重新核对授权与有效性 |
| 部署 | 公网低延迟入口 + CPU/内存较好的 core 主机 | 记忆库存 core；入口不做权威记忆判断；4090 不作为产品依赖 |
| 模型 | 可配置云端提取；敏感内容默认不发送 | 本地预过滤及失败回退；云端不可用时保留原会话，不伪造精选事实 |
| 群友记忆 | 已核实群友可默认建立个人记忆，之后可退出 | 只从本人发言提取；“别记我了”须停止新写入并删除已有个人记忆和群用风格提示 |
| 群内画像 | 可影响对该群友的语气，但不透露私有细节 | 群用风格提示只能从该群公开发言生成，不能读取其私聊画像 |
| 群公共事实 | 群友本人在本群公开说过的信息可回答给本群其他人并注明来源；心理与关系信息可以，住址和门锁类不可以 | 存在群空间，按类别拦截，禁止带到其他群；不得从成员私有记忆补充 |
| 情绪事件 | owner 的每次情绪事件独立保存；普通事件约 90 天过期 | 两次独立情境且至少一次获本人确认或反馈，才自动形成长期模式；重要共同经历经确认可长期保留 |
| 情绪信号 | 首版使用文字与明确反馈；语音语调以后可选 | 明说和推测须分开，保存时间、来源、置信度与可撤回状态 |
| 情绪使用 | 推测先微调回应；仅在影响回应选择时轻声确认 | 不自动点出情绪，不把一次状态固化为人格或长期需求 |
| 旧情绪事件的日常使用 | 用户只说“好累”等模糊近况时，可微调语气，不刻意点出过去的具体经历 | 只有用户自己提起或追问时才展示相关旧事，避免翻旧账式关心 |
| 情绪模式归并 | 主要按当时的需求与有效回应匹配，不按情绪标签或触发情境单独归并 | 同为难过但一回需要陪伴、一回需要建议，不能直接计为同一种模式 |
| 回应效果证据 | 可根据后续语气推断效果；这算隐式反馈，但保留推测标记且可撤销 | 不把语气变化写成“用户明确认可”；原始语气、推断与可能的其他原因分开 |
| 相处模式失效 | 一次明确反对即停止在该情境套用；两次独立的隐式反向反馈后暂停并轻声确认 | 当前发言优先，调整要自然；不主动宣告正在调用模式，追问时才解释 |
| 单次请求与长期偏好 | “这次直接给建议”只调整当前互动，长期模式保留；“以后都这样”才更新长期偏好 | 回应指令与记忆更正分开建模，避免一次需求重写长期相处方式 |
| 情绪记录内容 | 情绪、触发情境、可能需求、鲸鱼回应、用户反馈分别记录 | 需求是可纠正的假设；反馈可更新回应偏好，不能倒写成用户原话 |
| 敏感情绪触发粒度 | 只存概括类别，如“亲密关系变化”，不复制人名等细节 | 来源指向原消息；只在原消息仍保留且 owner 可访问时显示，删除后不从事件重建细节 |
| 情绪控制 | owner 可在记忆页看来源和推测标记，并更正或删除 | 每次自动记录可审阅；删除要从事件、模式和检索投影传播 |
| 周度画像控制 | 记忆页逐项显示情境、推测标记、依据和生效状态 | 每项可直接修改、暂停或删除，不用整段重写画像 |
| 默认回应 | 模糊倾诉先自然回应和陪伴，线索充分时再给建议 | 不机械地每次追问“想要倾听还是建议” |
| “烦死了”首句 | 没有原因时，第一句简短直接地问发生了什么，尽快弄清情境 | 不先泛泛安慰、不猜旧事或给方案；后续避免连环追问 |
| “导师退稿、明天交”后续（非首版主轴） | 若遇到，先了解具体意见和用户感受，弄清后再帮 | 用户实际更常聊兴趣；不以此罕见场景主导产品架构 |
| 角色与语言 | 鲸鱼平常聊天始终保持自己的角色风格；不模仿用户情绪 | 每个人可有语言特征；高相似度模仿只用于本人明确要求的草稿写作，不用于普通聊天 |
| 语言特征语料 | 本人的私聊和群聊发言合成统一语言画像 | 群用风格提示仍是独立的本群公开发言视图；统一画像只进入本人草稿写作路径 |
| 关系变化 | 留下可解释的相处偏好与共同经历，不设隐蔽亲密分数 | 用有来源、可纠正的事件解释表达变化；角色卡不随推测被暗中改写 |
| 人物画像重点 | 按不同情境记录可能需求、有效回应和表达偏好；宽泛性格判断只作可修正推测 | 回应策略由当前话语主导，画像提供参考，不用性格标签机械决定回复 |
| 推测画像的使用 | 达到两次独立情境且至少一次反馈门槛的相处偏好，即使未明确确认，也可稳定用于对应情境，直到本人纠正或反向反馈使其暂停 | 记录继续标“推测”并可撤销；宽泛性格标签不单独驱动回复，当前话语优先 |
| 画像整合周期 | 每周统一回顾近期互动，形成较完整的画像更新 | 明确更正和撤销仍即时生效；周任务只整合观察和反馈，不延迟本人命令 |
| 每周回顾材料与兴趣探索 | 用情绪事件、反馈、少量非敏感原话和本人分享/讨论的主题；可扩展“可能喜欢”的话题 | 敏感倾诉只用概括情绪事件；可能喜好只用于偶尔自然试探，不自动变成稳定偏好；转发内容不当成本人文风 |
| 首版当下需求判断 | 先用简单规则与当前对话，不为每条消息增加独立的需求判断模型调用 | 正常回复模型自然作答；后续反馈用于修正画像，再按产品评测决定是否需要专门模型 |
| 敏感倾诉模型边界（已重议） | 亲密关系、心理健康倾诉仍用现有云端 API 回复，默认不自动形成长期事实；情绪事件仍按普通规则约 90 天保存 | 回复内容仍沿现有调用路径发给服务商；情绪事件与长期事实分开，后台不排队等本地模型 |
| 本人主动记敏感事实 | 明确“记住”时只把本人指定内容写入 owner 私有记忆，可更正和删除 | 不另触发自动提取模型；普通敏感倾诉仍不自动形成长期事实 |

## 当前代码与证据

- `memory/curation.py` 已保存 `source`、`evidence_id`，召回命中也包含来源原因；`core/companion.py` 给回答模型注入的主要是摘要。解释来源时信息在最后一步丢失。
- `memory/governance.py` 已实现删除和更正；`memory/spaces.py`、`life/context_resolver.py` 已有服务端空间边界。TimlMemBench 的离线端到端测试确认合法更正、撤销改变真实召回，非法说话人和跨空间操作被拒绝。
- `memory/consent.py` 当前对已核实群友采用默认开启、本人可退出；`member_private` 不在群聊召回范围。本次决定要求另外构建仅由该群公开发言生成的低风险风格提示，不能直接开放 `member_private`。当前 `life/qq_workflow.py` 的“别记我了”只写退出标记，旧记忆需另说“删掉我的记忆”；这与新决定不符，实施时需合并退出与清理路径，并更新回复文本和测试。
- N100 的 `docs/memory-recall-baseline.md` 表明百条级召回没有性能瓶颈。暂不引入持久向量数据库；可选 embedding 继续作为召回增强，并保持关键词回退。
- 当前 `MemoryKind` 只区分 episode、preference、persona_continuity；`RelationshipState` 主要是粗粒度熟悉程度和已授权自述摘要。它们不足以区分“单次推测情绪”“经确认的长期相处模式”“用户语言特征”。首版应新增明确类型与访问接口，可共用 SQLite 后端，但不能让普通事实召回默认扫描情绪事件。
- TimlMemBench 中文 dev：同提示词对照为 116/144，治理适配器为 119/144；两组独立提取且同模型裁判，净差 3 题不能归因于产品 memory。`write_op_accuracy` 为 3/10，`provenance_recoverability` 为 1/8；官方请求缺少受众 ACL，`scope_isolation` 分数不能证明第三方隔离。详细结果见 `evals/TIMLMEMBENCH_DEEPSEEK_RUN.md`。
- 2026-11-12 的 18 题配对复测固定了 61 段会话的 281 条提取候选：基础 5/18、只加来源锚点 7/18、再加治理操作 6/18；净差小且有正反翻转，不能声称治理已带来稳定增益。旧许可的同义副本残留、来源 ID 有而回答不引、操作轨迹噪声、Top-5 视图不适合全序列写入分类是当前主要诊断。详见 `evals/TIMLMEMBENCH_TARGETED_2026-11-12.md`。
- 后续适配器修正对同一批 18 题完整重跑为 10/18（写入 6/10、来源 4/8）；逐轮只重测失败题得到的混合 15/18 未在完整重跑中复现。仍缺逐候选的 skip/临时决策日志和完整更正来源链，不能把此结果解释为产品 memory 性能。

## 目标架构

1. **写入管线**：认证发送者与会话 → 保存原始会话 → 本地敏感性筛查 → 异步候选提取（可配置云端）→ 校验源发言、说话人、事实类型、空间与幂等键 → 写入低风险精选事实。证据不足或敏感性不确定时不自动晋升。
2. **状态变更**：本人明确撤销或更正 → 将目标限定在本人可治理的事实及授权空间 → 原子地更新当前状态与来源链 → 清理或失效相关检索缓存。含糊冲突创建待确认状态，不让两个互斥事实同时作为当前事实参与回答。
3. **读取管线**：服务端解析身份、会话与受众 → 生成允许的空间及逐事实分享授权 → 只从授权集合召回当前有效事实 → 有界排序与注入 → 回答。对外分享和主动执行在实际使用时再核验授权、期限和撤回状态。
4. **解释管线**：被问“为何记得/为何改变”时，在同一读权限下取来源发言、时间及更正事件；若原文已彻底删除，只能说明证据已删除，不能从日志或旧索引复活。删除在线立即生效；旧离线备份最多保留 30 天，恢复前强制重放删除记录，到期清除备份。
5. **群用风格提示**：按 `(group_id, member_id)` 建独立、低风险、可过期的提示；输入只限该群公开发言。群聊模型可用该提示调整表达，但不能读取成员私聊记忆或把风格提示当作事实性授权。
6. **情绪事件库**：单条记录保留主体、事件时间、来源消息、明说/推测标记、情绪描述、触发情境、可能需求及置信度；鲸鱼回应与用户反馈作为后续关联事件写入，不伪装成原始证据。owner 空间独占，普通事件约 90 天过期；确认的重要经历单独长期保留。同一对话只计一次观察，至少两个不同日期或独立情境且其中至少一次得到 owner 确认或反馈，才自动形成长期相处模式。后续语气可作为隐式反馈，但推断须标记、可撤销；若计数依赖隐式反馈，模式不能伪称为用户明确确认。两次纯模型推测且没有可归属的后续反馈不得晋升。模式主要按需求及有效回应归并，情绪标签、触发情境只作辅助证据。一般记忆召回默认不注入情绪历史，由回应策略按当前情境请求少量授权事件。
7. **回应选择**：先看当前话语和本会话上下文，再取相关的长期相处偏好及少量近期情绪事件，选择自然陪伴、轻声确认或具体建议；不模仿当前情绪，也不从一次推测触发主动消息或行动。语言特征可学习，但只在本人要求以其口吻写草稿时注入该写作路径；普通聊天始终使用鲸鱼角色卡。
8. **敏感内容边界（已重议）**：亲密、心理健康倾诉的聊天回复仍走当前云端 API；自动长期事实提取默认跳过，不假设本地模型或 30 天待提取队列。owner 明确“记住”时只把指定内容写入其私有记忆，可更正删除。敏感倾诉仍按普通规则自动生成约 90 天的情绪事件，含情绪、触发情境、可能需求和来源。
9. **关系连续性**：关系中的长期变化由已确认的相处偏好、共同经历、边界和反馈形成可解释视图，不用隐藏的亲密或信任分数驱动表达。角色卡是鲸鱼自身的稳定表达选择，关系视图只提供与当前主体有关的上下文，不能改变授权。

## 开发顺序与验收

### 第一阶段：把现有能力测准（不改产品语义）

- 固定同一批已提取记忆，分别测试有无操作识别，隔离回答提示词和提取随机性；记录操作候选的拒绝原因。
- 上一项的冻结候选和三组开关已接通并跑完 18 题；拒绝码已细分但尚未付费重跑。下一步优先离线复现“同义旧许可残留”与“来源 ID 存在但回答否认来源”，再决定产品 memory 与适配器各改哪一层。
- 为 TimlMemBench 的解释类题目提供授权范围内的来源 ID 和事件链；做离线端到端负向测试，证明撤销内容不会从解释、日志、检索中重新暴露。
- 人工复核小批写入操作和来源题，记录裁判分歧；dev 用于迭代，holdout 在方案冻结后一次性验证。

### 第二阶段：产品写入与更正

- 实现异步、幂等的低风险事实提取；同一消息重试不得重复建档。回答不等待云端提取，提取失败不影响原聊天。
- 统一明确更正、撤销与待确认冲突的状态转换；当前事实召回不得包含旧版本。附来源发言、时间和主体，防止他人提问或建议被误作本人授权。
- 验收：模拟两设备、并发重试、错说话人、含糊更正、云端不可用；所有状态与权限由存储/服务端测试断言，不依赖模型自报。

### 第二阶段并行切片：owner 情绪事件与回应策略

- 在现有存储后端上建立独立情绪事件访问接口，不与普通 curated 事实混用；实现来源、明说/推测、90 天清理、确认、纠错及删除传播。晋升测试必须覆盖同一会话重复、两次独立但全为推测、两次独立且有一次本人反馈、之后明确否认四种情形。
- 用当前对话和少量相关情绪记录选择回应方式；记下鲸鱼实际回复和用户反馈。没有用户反馈时不把“这次安慰有效”写成事实。
- 在记忆页增加可查看、更正、删除的情绪事件视图；首版只服务 owner，群友仅做当前会话的短期语气判断。
- 增加一组产品对话场景：模糊倾诉、想要建议、误判后纠正、跨会话重复需求、过期事件、亲密或健康内容的本地分流。人工盲评是否自然、是否切中需求、是否越界或翻出不合时宜的旧事；TimlMemBench 继续作记忆治理回归，不能单独代表情感陪伴质量。

### 第三阶段：分享、解释与删除

- 逐事实分享授权绑定对象、来源空间、期限和撤回版本；群聊及第三方请求使用真实身份上下文测试。无授权时不得检索私有事实。
- 增加按需来源解释；“忘掉长期记忆”和“彻底删除记录”分别定义覆盖的记录、索引、历史与备份恢复行为，避免名称相同却行为不同。
- 群用风格提示与成员私有画像分库或分空间，并测试跨群、跨人、退出后的隔离。群友说“别记我了”时，同步清理个人记忆、提炼状态、相关个性化经验及其所有群用风格提示；重新开启后不回填退出前已删除的旧画像。
- 主动任务只消费独立的显式授权，不从事实记忆直接生成执行权。
- 每个人的语言特征与情绪事件、鲸鱼角色卡分别管理；语言特征可逐步学习，但只在本人明确要求写草稿时使用。测试普通聊天零模仿、草稿请求高相似度表达、不复制对方的愤怒或低落情绪。

## 暂不做的架构扩张

- 不因 144 题 dev 的 3 题净差重写存储层，也不为追分把 benchmark 金标准喂给适配器。
- 不在当前百条级规模引入新的持久向量数据库或要求 4090 长期在线。
- 不把成员私聊画像注入群聊模型，再试图靠提示词禁止泄露。
- 不把被撤销的原文放进持久操作日志；如需解释，只保留与删除语义相容的最小事件元数据。

## 尚待实现前确认的细节

- “敏感内容”本地过滤规则与误判时的管理入口。
- 一段来源同时支持多条事实时，忘掉其中一条后的证据引用和清理边界需在实现中验证。
- 完整删除承诺已定为在线立即失效、旧离线备份最多 30 天、恢复强制重放删除记录；实施时仍需明确删除记录本身的最小字段、存储位置及恢复测试。
- 逐事实分享授权未指定期限时默认 24 小时；更正后旧版本失效且新版本须重新授权。已发送消息无法追回，需在分享前清楚表达。
- 情绪长期模式按需求与有效回应归并；候选相似度仍须用首版样例标注验证。计数门槛已定为两次独立事件，且至少一次本人确认、明确反馈或可归属的后续语气隐式反馈；隐式反馈及依赖它的模式必须标记为推测、允许撤销。
