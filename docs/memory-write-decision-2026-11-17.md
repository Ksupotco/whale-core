# 自动事实写入决策（首版）

自动提取仍只接收本人、原话可核验、低风险的事实。每个候选在提交前由 `memory/write_decision.py` 读取同空间、同主体、同 slot 的当前有效事实：

1. 内容相同或只差空格、句末标点：`preserve`，追加来源，不新建事实。
2. 无同 slot 旧事实：`add`；有明确期限的候选保持 `ephemeral`。
3. 本人明确更正，且旧目标唯一：`update`，旧版本失效并保留更正链。
4. 含糊的直接冲突：`pending`，暂停该 slot 的普通召回。
5. 同 slot 但关系不明确：才调用模型判断兼容补充、更新、撤销、跳过或待定；目标 ID 必须属于当前同主体、同空间、同 slot 的有效事实。无效或无法解析的决策保持待定。

所有操作仍经 `FactService` 提交；兼容补充在决策记录中标记 `compatible_supplement`。普通新事实无需额外决策模型调用。

每个候选只用其对应的原话片段判断是否为本人明确更正，避免同一条消息中另一件事的“以后不……”误触发更新。整条消息仍作为提取输入，但不充当每个候选的更正指令。

## 判定顺序

| 当前事实关系 | 本人明确更正？ | 处理 |
| --- | --- | --- |
| 同一主张，仅表述标点不同 | 任意 | `preserve`，追加来源 |
| 找不到同主体、同空间、同 slot 的有效旧事实 | 否 | `add` 或有期限的 `ephemeral` |
| 同 slot 的唯一旧事实，明确改口 | 是 | `update`，保留版本链 |
| 同 slot 的直接反向主张，但没有明确改口 | 否 | `pending`，旧 slot 暂停普通召回 |
| 同 slot 的补充或关系不明确 | 否 | 模型仅比较这组事实；兼容时 `compatible_add`，不确定则 `pending` |

这一步只覆盖当前生产自动提取器支持的 owner 自述事实。`FactService` 的决策入口已按主体和空间工作，但更广的宠物、安排、权限、群聊事实仍缺少稳定的 `slot_key` 与适用情境提取。下一个产品改动应让提取结果带上 `{subject_id, slot_key, context, claim, evidence_id}`，再复用这张判定表；不要把“同话题”当作“同一可替换事实”。

普通聊天中的“以后别提醒我”目前尚未完整进入自动提取路径。它需要同时让旧提醒许可失效并保存新的禁止边界；现有显式记忆命令与 `FactService` 已可执行更正或撤销，但自动候选还需表达这一复合意图。TimlMemBench 的群聊、多主体、历史写入分类由独立适配器处理，不能用目前的 owner 自动提取结果直接推算其 write 分数。
