# Whale 需求驱动的 memory 架构 v1（评审草案）

日期：2026-11-12。范围：在现有 Python core、SQLite、MemorySpace 和 QQ/设备入口之上，满足私人情感陪伴的记忆需求。架构由产品不变量决定，外部框架只在能解决具体问题时作为参考。本文是可评审设计，尚非已实现功能。最新决定：亲密关系或心理健康倾诉继续用现有云端 API 回复，默认不自动提取为长期记忆。

## 0. 可执行架构决定

首版保留一个 SQLite 数据库和现有模型 API，不引入图数据库、向量数据库或常驻本地模型。按数据职责分四层，而不是给每种记忆建立一套独立流水线：

```text
QQ / 私聊 / 设备入口 → 带主体、会话、空间和受众的消息
                    ├─→ 当轮回复：当前话语 + 本会话 + 相关事实/相处提示 → 现有聊天模型
                    └─→ 回复后任务：来源 → 候选 → 校验/合并 → SQLite 当前状态
                                                   ├─ 事实与边界（有版本、证据和授权）
                                                   ├─ 情绪事件（短期、可纠错）
                                                   └─ 每周画像/兴趣假设（推测、可暂停）
```

1. **证据层**保留来源消息标识、必要原话片段和删除状态；是解释与纠错的依据，不直接当作长久有效的事实。普通会话历史仍由现有机制提供。敏感情绪只沉淀概括情境；是否可查看原话取决于原聊天是否仍存在及本人权限。
2. **事实层**保存当前有效的明确事实、版本链、主体、空间、有效期和逐版本分享授权；区分本人原话与系统推断。明确更正同步失效同一事实族的旧活跃版本；含糊冲突进入待定状态。自动提取与显式命令必须走同一个写入服务。
3. **体验层**保存 owner 的情绪事件、分开的回应与反馈；每周归纳有证据的情境化相处偏好和可能兴趣。画像中的推测可稳定影响对应情境，但始终标记为推测、可改可停。人格宽泛标签不是回复指令。语言特征另作草稿写作资源，不进入日常回复。
4. **回复装配层**位于 `core`，根据当前话语和会话取少量相关记忆，明确标出“事实”“相处提示”“不确定兴趣”，再交给现有回复模型。当前明确要求优先于任何旧模式。是否接着讨论、追问还是给建议属于当轮对话策略，不写成长期事实，也不额外调用专门的需求分类模型。鲸鱼的角色卡仍控制普通聊天风格。

一期实现只需要三个新的领域入口：`FactService`（写入、更正、撤销、当前版本）、`ExperienceService`（情绪事件、反馈、周期整合）和 `MemoryContextBuilder`（按主体/空间/用途读取）。持久任务与 SQLite 仓库为这些入口提供基础设施；分享、彻底删除、语言草稿和群场景按同一数据契约逐步接入。下文表格描述完整目标对象，不表示首个代码改动要同时建完所有表。

**第一个可运行切片**：先定义 `MemoryContext` 的轻量读取契约，区分现有精选事实、其他精选记忆和本会话片段；让 `core/companion.py` 选取少量条目，并让 `core/prompt_composer.py` 分区呈现。此时只从现有数据读取，不凭空生成画像，也不改变数据库。后续事实服务和体验服务接入时，再扩展相处提示、兴趣假设及其来源/置信度/适用情境。用兴趣讨论、普通倾诉、显式“这次/以后”、无关旧事四类对话检查自然度和越界使用。质量验收由人工盲看真实对话样例与固定场景回归共同完成，TimlMemBench 只检验事实操作与来源链。

## 1. 从需求反推的边界

Whale 需要四类不同的记忆，它们可以共用 SQLite，但不能共用一个无区分的 Top-5 召回：

- **事实与边界**：主人或群友明确说过的偏好、安排、关系事实、禁做事项。必须有正确主体、空间、来源和当前版本。群友本人在本群公开的事实可进入该群公共记忆，不能跨群复用；心理与关系信息允许在本群再次回答，住址、门锁及访问类信息不得形成群可答事实。群友个人记忆另存私有空间。
- **情绪事件与相处模式**：短期情绪和可能需求单独保存；反复且有反馈才形成可解释的长期回应偏好。推测始终标记为推测。
- **人物画像、语言特征与共同经历**：画像优先记录不同情境下的需求、有效回应和表达偏好；宽泛性格判断只能作为可修正的推测。语言特征可从本人语料学习，但仅用于本人明确要求的高相似度**草稿写作**；鲸鱼平常聊天始终用自己的角色风格。共同经历有证据、可纠正，不计算隐蔽亲密分数，也不模仿人的当下情绪。
- **授权与操作记录**：分享、主动行为、删除墓碑和写入决策是控制数据，不是可被模型自由召回的用户事实。

首版先保证 **错记可纠、旧事实不再生效、私事不越权、情绪回应自然**。为此只借鉴必要机制：少量候选提取、事实与推测分离、版本与来源链。无需接入 Mem0、Hindsight 或 Graphiti 的软件服务，也无需图数据库或持久在线 4090。[Mem0 的提取说明](https://github.com/mem0ai/mem0/blob/main/docs/core-concepts/how-it-works.mdx)、[Hindsight 论文](https://aclanthology.org/2026.acl-demo.27/)、[Graphiti 官方说明](https://github.com/getzep/graphiti)仅用于解释设计来源。18 道 TimlMemBench 诊断题的 10/18 仅作回归起点。

## 2. 单一写入路径

```text
渠道消息（已认证主体、会话、受众、时间）
  → 保存原始会话 + 投递幂等后台任务
  → 本地敏感性与退出/暂停闸门
  → 模型提取少量结构化候选（事实/边界、明确撤销/更正、情绪线索）
  → 代码校验原话、主体、空间、时间、长度和敏感性
  → 同主体同空间的候选事实检索
  → 整合与冲突决策
  → SQLite 原子提交事实版本、证据链接与最小决策记录
  → 分别更新事实、情绪、风格的可见视图
```

聊天回复先发出。后台任务在数秒内处理；本会话未写完时仍可从近期对话读到刚说的原话。低风险自动写入不在聊天中逐条报备，记忆页显示新记录、来源及一键纠错/删除。显式“记住、忘掉、更正”继续同步处理，但统一调用同一套事实状态服务。情绪事件不因一次模型推测就转成长期人格判断。

**模型只提出候选和可能关系。** 身份、空间、禁记、当前版本、权限、操作原子性由代码裁决。云端提取前先运行本地筛查；亲密关系、心理健康等敏感倾诉默认不自动提取**长期事实**，但照普通情绪事件规则保存情绪、触发情境、可能需求和来源，约 90 天后清理。若 owner 明确说“记住”，只把本人指定的敏感事实写入其私有记忆，并提供更正与删除；此显式写入不额外调用自动提取模型。聊天回复继续调用现有云端 API，这意味着回复内容会按当前 API 调用路径发送给服务商；不能把“未自动记忆”误说成“未送云端”。

## 3. 最小领域对象

| 对象 | 核心字段 | 用途 |
| --- | --- | --- |
| `SourceMessage` | `source_id, principal_id, space_id, conversation_id, message_id, occurred_at, quote, visibility` | 原话锚点；只保存形成记忆所需的片段，授权解释时读取 |
| `MemoryCandidate` | `candidate_id, subject_id, predicate, value, context_key, claim_kind, evidence_ids, confidence, sensitivity` | 模型输出，尚不参与召回；主体与原话需代码校验 |
| `MemoryFact` | `fact_id, family_id, subject_id, space_id, predicate, value, context_key, status, valid_from, valid_to, recorded_at, version, claim_kind` | 当前事实及历史版本；群公共事实绑定来源群空间，事实 ID 不等于消息 ID |
| `FactEvidence` | `fact_id, source_id, support_type` | 多条独立证据可支持同一事实，不能生成多个相互矛盾的活跃副本 |
| `MemoryDecision` | `job_id, candidate_id, action, target_fact_ids, reason_code, decided_at, model_version` | add/update/revoke/preserve/skip/pending 审计；跳过项默认不保存原文 |
| `FactRelation` | `from_fact_id, to_fact_id, relation` | `supersedes`、`retracts`、`supports`；用于解释链，不作为权限来源 |
| `EmotionEvent` | `owner_id, source_id, occurred_at, emotion, trigger_category, possible_need, explicit_or_inferred, confidence, expires_at` | 一次情绪经历；敏感触发只写概括类别，不复制人名或诊断；普通事件约 90 天过期 |
| `InteractionPattern` | `need, effective_response, supporting_event_ids, feedback_kind, inferred, status` | 两次独立情境、至少一次本人确认或反馈后形成的相处偏好 |
| `PersonModel` | `principal_id, context_key, need_hypothesis, effective_response, expression_preference, evidence_ids, inferred, confidence, active` | 情境化人物画像；达到重复证据门槛的推测性相处偏好可稳定影响回应，但保留推测标记；宽泛性格标签不单独决定回应 |
| `InterestHypothesis` | `principal_id, topic, evidence_ids, confidence, status, tested_at` | 从分享与讨论推断可能喜好；与本人明确偏好分开，只用于偶尔自然试探，不自动写成稳定喜好 |
| `LanguageProfile` | `principal_id, evidence_ids, language_features, representative_examples` | 汇总本人跨私聊与群聊的统一语言特征；仅本人明确要求写草稿时高相似度使用，不注入普通聊天，不模仿情绪 |
| `GroupStyleHint` | `group_id, member_id, public_evidence_ids, tone_preferences, expires_at` | 只从该群公开发言生成，用于调整对其说话的语气，不含私聊事实，也不触发语言模仿 |
| `FactGrant` | `fact_id, fact_version, recipient_id, purpose, expires_at, revoked_at` | 指定事实、对象和期限的分享；默认 24 小时，更正后需重新授权 |

事实族 `family_id` 表示同一主体、同一语义槽位和适用情境的一组版本。`context_key` 区分“在家”“在群里”“周五提醒”等条件；槽位还声明单值/多值，不能因为同一主题就删除独立偏好。对同一事实的重复自述只增加证据；明确更正必须原子地失效该事实族所有旧活跃副本，避免 2705 一条旧摘要被替换、另一条仍被召回。

`claim_kind` 至少区分：`user_stated`、`observed_event`、`agent_inference`、`interaction_preference`。情绪事件、语言特征和鲸鱼角色卡拥有独立访问接口，不混进普通事实表的默认召回。一次性码、密码和短时操作信息不晋升长期事实；可把“不要保存门锁信息”作为长期边界保存，而不保存具体门锁信息。敏感情绪事件只写概括情境，例如“亲密关系变化”；`source_id` 指向原消息，仅当原消息仍保留且本人有权查看时才展示原话，原消息删除后不得从情绪事件重建细节。情绪中的“可能需求”、鲸鱼实际回应、本人明确反馈及从后续语气推断的隐式反馈须分别落记录，不能互相冒充。

## 4. 状态决策与读取

| 输入情况 | 决策 | 当前召回 |
| --- | --- | --- |
| 新的低风险明确事实 | `add` | 新版本可见 |
| 同一事实重复表达 | `preserve`，增加证据 | 仍只见一条当前事实 |
| 本人明确更正 | `update`，旧族失效、新版生效 | 只见新版 |
| 本人明确撤销许可或要求忘记长期记忆 | `revoke` / `forget` | 旧版立即不可见；删除按指令语义处理 |
| 只有短时价值、禁记或主体不明 | `skip`，记原因码 | 不可见 |
| 与旧事实冲突但更正意图不明 | `pending`，暂停受影响的主动行为 | 不把两个互斥说法当成确定结论；只在影响当前回答或本人要安排该行为时自然询问 |

召回顺序：服务端先解析本人、受众、允许空间和逐事实分享授权，再在允许集合内过滤 `active` 版本与有效时间，然后关键词/现有可选语义检索、排序、注入少量摘要。**回应上下文按用途装配**：当前话语和本会话原话优先；其次取相关事实/边界、少量有效相处模式；仅当前对话需要时取 owner 的近期情绪事件。若用户只说“好累”而未提旧事，旧情绪事件最多用于微调语气，不作为主动点名旧经历的依据。群聊可取从该群公开发言生成的群用风格提示，但不得取私聊画像。群用提示只影响对话适配，不等于模仿；`LanguageProfile` 不进入普通聊天，只在本人要求以其口吻**写草稿**时交给草稿生成路径。鲸鱼聊天保持自身角色卡，草稿可高相似度，均不复制当下情绪。普通回复不自动展示证据链；“为什么这么记”单独读取授权来源、原话、时间和更正关系。主动提醒或行动另需明确执行授权，事实本身不授予行动权；新话语与旧提醒偏好有含糊冲突时，先暂停该提醒，待当前回答或重新安排确实需要时再确认。

回应优先理解当前话语。情绪倾诉的具体问法只是可选场景，不作为首版优化重点；用户实际更常与鲸鱼分享兴趣、讨论作品或想法。首版应能接住分享的具体内容、提出相关观点或自然追问，并逐渐积累可修正的兴趣假设，而不是把每次分享都转成“求建议”。情绪场景仍保留基本规则：没有原因的“烦死了”可简短问发生了什么，不先泛泛安慰、猜旧事或给方案；推测情绪先微调语气，只有回应选择确受影响时才轻声确认。两次情绪事件只有在不同日期或独立情境、且至少一次有本人确认、明确反馈或可归属的后续语气隐式反馈时，才按“需求 + 有效回应”归并成模式，并进入 `PersonModel` 的对应情境。达到这一门槛的推测性相处偏好可以像已确认偏好一样稳定影响相应情境的回应，直到本人纠正或相反反馈触发暂停；记录始终保留推测标记并可撤销。同一对话重复不计两次。当前发言优先于旧模式，回应自然调整，不主动宣告“我调用了你的相处模式”；仅在本人追问原因时解释来源。“这次别安慰，直接给建议”只覆盖当前互动，保留长期模式；“以后都这样”才更新长期偏好。两次独立的隐式反向反馈则暂停旧模式并轻声确认。宽泛的性格标签不作为回应规则。群友首版只做当前对话的短期语气判断，不存长期情绪档案。

分享授权绑定事实版本、指定对象和期限；旧版本一旦更正立即失效，新版本不自动继承授权。群友本人在某群公开说过的事实，可在**同一群**回答其他群友，并注明来自本人在本群的发言；心理与关系信息也可按此规则使用，但住址、门锁、钥匙、访问凭据等不得形成可答事实。只接受本人原话，明确“别在群里复述”等边界优先；不进入别的群或冒充私聊授权。群友说“别记我了”后，停止其新写入并删除个人记忆与所有群用风格提示；本人恢复后不回填退出前已删除的画像。群公共派生事实的退出处理不在当前画像与表达设计的讨论范围。记忆页可逐项查看自动事实、情绪事件与周度人物画像；画像显示情境、推测标记、依据和生效状态，允许直接修改、暂停或删除，不必整段重写。普通聊天不逐条播报后台写入。

`forget` 使长期精选事实、关联索引和专为该事实保存的证据片段不可召回；“彻底删除记录”另删除原始聊天与派生物，并写不可逆的最小删除墓碑供备份恢复重放。被删除原话不能因追溯查询复活。当前记忆有效时保留它的来源原话片段；更正后的旧片段最多再留 30 天，随后只保留不含原话的更正链（来源 ID、时间和关系）。若一段来源同时支持其他仍有效事实，只能在授权范围内为那些事实继续使用，不能借此复活已忘记的事实。旧离线备份最多保留 30 天，每次恢复先重放删除墓碑；到期物理清除。完全删除立即优先。经主人确认的重要共同经历可以作为单独长期记录，普通情绪事件仍按约 90 天清理。

## 5. 后台任务与模型调用

- SQLite 持久任务含 `source_message_id + extractor_version` 幂等键、状态、重试次数和下一次运行时间；进程重启可续跑。提交前重新检查 opt-out、暂停、来源是否已删除、空间版本与权限，不能凭入队时的旧授权写入。
- 首版单次批量事实提取 + 本地候选比对；只对存在冲突或多目标歧义的候选调用第二次模型判断。人物画像另由每周后台任务回顾情绪事件、回应反馈、少量非敏感原话，以及本人在聊天中分享和讨论的主题，提出一次可追溯的画像更新与可能喜好假设。可能喜好只用于偶尔自然试探，不自动升级为“本人喜欢”的稳定事实。敏感倾诉只使用已概括的情绪事件，不把原话整段送进画像回顾；区分本人原创表达与转发/引用内容，避免把别人的文风学成用户语言特征。明确更正、撤销及“以后都这样”的偏好变更仍即时生效，不等周任务。失败保留原聊天，不伪造精选事实。设置每轮候选数、模型调用次数、输入长度与成本上限。
- 提取器经接口使用现有 OpenAI 兼容模型配置；不绑定 DeepSeek、4090 或某个服务商。亲密关系、心理健康等敏感倾诉默认不调用自动长期提取。聊天回复沿用现有云端 API；不以部署本地模型为本阶段前提。

## 6. 代码结构与迁移

在 `src/whale_core/memory/` 增加少量有明确用途的模块，保持 memory 不反向依赖 life：

```text
facts.py           候选、事实版本、证据、写入决策和冲突状态
formation.py       结构化提取接口、写入闸门、整合和提交编排
fact_repo.py       SQLite 事实/证据/决策事务与 schema 迁移
retrieval.py       按身份/用途装配当前事实、相处偏好与授权来源
emotion.py         owner 情绪事件、反馈及长期模式；独立 TTL 与纠错
person_model.py    每周按情境整合需求、有效回应和表达偏好；保留推测标记
style.py           个人语言特征、群用风格提示及草稿写作的授权读取
sharing.py         逐事实版本授权、期限、撤回
deletion.py        两种删除语义、派生物清理、恢复墓碑
jobs.py            持久异步任务、每周画像回顾、幂等和重试
```

模型 API 的具体客户端留在 `core`/运行时，通过协议注入 `formation.py`，避免 memory 域绑定某服务商。现有 `store.py`/`sqlite_store.py` 继续提供基础存储并升级 schema；`curation.py`、`governance.py`、`core/memory_commands.py` 逐步改为调用统一事实服务，不在首个改动中整体重写。`memory/extraction.py` 的群友规则提取保留为候选来源，经同一写入闸门落库；已有 `experience.py` 可承载明确反馈，但情绪隐式反馈必须另标推测。已有 `persona_evolution.py` 保持鲸鱼角色卡的独立审批路径，不被个人语言特征覆盖。QQ 工作流只提供已认证上下文。`core/companion.py` 先通过兼容召回接口读取 `active` 投影，避免所有渠道同时改造。首版不对每条消息另调模型预测心理需求：`core` 用简单规则、当前对话和 memory 提供的画像组织上下文，由正常回复模型自然作答；事后根据明确偏好及反馈修正画像，不把临场猜测直接写成事实。

第一批可审查代码变更按依赖顺序拆分。首个可体验版本优先让日常聊天更懂当下需求，而不是优先推出模仿草稿：

1. **日常回应切片**：当前话语、本会话上下文、少量有证据的相处偏好进入回应装配；优先以兴趣分享和讨论验收，检查是否回应了具体内容、能自然接续话题、不会泛泛夸赞或自动给方案。普通聊天维持鲸鱼角色风格，不刻意翻旧经历。情绪倾诉保留基础场景测试，但不作为首版主轴。
2. owner 情绪事件、反馈与可纠正的情境化画像；按两次独立情境及反馈门槛形成模式，每周回顾近期互动。验证误判后纠正、模式自然生效和反向反馈暂停。
3. 事实版本、证据、写入决策与原子更正；随后接入异步自动写入、当前事实召回与显式命令迁移，验证旧许可多副本全部失效、错主体、重试与删除后不复活。
4. 逐事实分享、解释、两种删除、群友退出清理与群用风格；验证跨设备/跨群/跨人隔离。个人语言特征只在本人明确要求写草稿时高相似度使用。
5. 以产品场景和 TimlMemBench 诊断题回归；把 `add/update/revoke/preserve/skip` 的逐候选决策与来源链作为可观察输出，避免只看裁判总分。

跑团群是用户后续的个人试点：群聊接入、人物/世界设定与剧情连续性可作为独立场景验证；跑团特有规则不进入所有用户的通用人物画像或情绪存储模型。

首批验收应覆盖：错主体、他人代撤销、跨空间、更正多副本、含糊冲突、已删除来源、并发重试、备份恢复、群友退出、一次性码 skip、情绪误判、两次独立反馈、普通聊天零模仿、本人草稿请求高相似度且不复制情绪、群聊风格不越权。上述是产品不变量；benchmark 仍作为外部诊断，官方无受众 ACL 的题不能证明权限隔离，也不能评估陪伴是否自然。

## 7. 需求覆盖审计

此处“覆盖”指设计里有明确数据、执行路径和验收位置，**不表示代码已实现**。

| 已确认需求 | 设计落点 | 当前主要缺口 |
| --- | --- | --- |
| 低风险自述自动记、数秒后台完成、可纠错 | `formation.py` + `jobs.py` + 事实版本 | 现有 owner 主要靠显式命令；没有统一的异步写入事务 |
| 错主体、旧事实、含糊冲突不误用 | 写入闸门、事实族、`pending`、原子失效 | 现有更正按单条 key，缺同义副本关联 |
| owner 跨设备私有、指定事实限时分享 | 现有空间解析 + `FactGrant` 绑定版本 | 缺逐事实版本授权及更正后重新授权 |
| 情绪事件、反馈和两次独立经历形成相处模式 | `emotion.py` + 独立回应上下文 | 现有经验存储不等于情绪事件/需求/回应反馈闭环 |
| 自然陪伴、按需给建议、不随意模仿 | 回应上下文装配 + 独立角色卡和模仿开关 | 现有普通 Top-5 事实召回不能表达回应策略 |
| 群友私有记忆、本群公共事实与群用风格、退出即清理 | 现有成员提取 + 群空间事实 + 类别闸门 + `style.py` + 删除传播 | 群公共事实尚无本人/来源群限域的统一写入与引用路径；现有“别记我了”尚未同时删除旧个人记忆和群用风格 |
| 解释原话和更正链、两种删除、备份不复活 | `FactEvidence`/`FactRelation` + `deletion.py` | 现有回答主要只见摘要，删除/恢复尚无完整跨派生物流程 |
| 只有显式授权才主动行动 | 事实与行动授权分域，执行前重验 | 记忆写入不能代替已有行动授权检查 |

所以，架构能够承载已确认的核心需求；**目前实现还不能满足全部需求**。完成以上模块与产品验收前，不以 TimlMemBench 分数宣布 memory 开发完成。

## 8. 留待单独确认的产品策略

已决定 owner 敏感倾诉继续用现有云端 API 回复，默认不自动形成长期事实；本人明确“记住”时只把指定内容写入私有记忆，并可纠正删除。敏感倾诉仍按普通规则自动保存约 90 天的情绪事件，但触发情境只存概括类别、不复制人名等细节；来源链接仅在原消息仍保留时可查看。群友本群公开的心理与关系信息可在本群回答，住址和门锁类不可；群公共派生事实的退出细节暂缓讨论。单次“这次”请求只调整当前互动，“以后都这样”才修改长期偏好。有效事实的来源片段随事实保留；更正旧片段最多留 30 天，再只留不含原话的更正链。原先“本地模型不可用则排队 30 天”的设想不再是本阶段默认路径。首批开发按第 0 节的四层架构与可运行切片推进。

## 9. 实现进度（2026-11-13）

- 已接通轻量 MemoryContext：现有精选事实、其他精选记忆、本会话片段分别进入提示词；旧模型仍使用原有字符串接口。
- 已增加 owner 情绪事件的最小存储：只在明确文字情绪时记录类别、概括触发、明确需求和来源引用；不把原话复制到事件。可记录反馈、删除事件；两次独立日期/会话且有反馈时可整合相处偏好，当前 owner 私聊可按情境读取。
- 已增加 owner 聊天触发的七天一次确定性维护：到期情绪事件物理清理，已有反馈的匹配事件整合为相处偏好；无需常驻进程或额外模型调用。尚未接入自动反馈判读、读近期讨论生成完整画像和记忆页编辑。此维护不等于完整的每周画像回顾已上线。
- 已增加事实族的最小事务服务，并接入显式“记住 / 更正 / 忘掉”。同一空间、同一主体的完全重复事实合并来源；更正会同时失效同族、相同旧摘要及调用方指定的相关旧记录，也会合并已有的新摘要记录。更正命令采用“更正：旧内容 -> 新内容”，精确查找旧事实。
- 已接入第一版模型自动提取：owner 私聊中出现明确、低风险的长期兴趣或偏好时，在回复生成后持久排队，后台用现有聊天模型提取最多 3 个原话片段；代码核对片段确实出自本人消息，再交给事实服务。任务重复投递只处理一次，重启后可继续；忘掉命令会取消尚未处理的匹配任务。当前只覆盖明确兴趣/偏好，不自动识别所有生活事实，也不做语义等价合并。
